# Turn a reference screenshot into functional UI

Inspect the provided reference and identify: layout regions, alignments, relative sizes, typography roles, compositional flow, illustration layers, asset responsibilities, lighting/material language and effects. Label which regions are decorative vs interactive and which are dynamic user data. Plan reusable native components and transparent assets; do not ship a full screenshot behind invisible buttons. Preserve platform safe areas, scaling and accessibility. Implement a first screen, run on device/browser, capture the same aspect ratio as the reference, and document the mismatches with screenshot evidence; iterate until the dominant composition works. Do not fake native screenshots or treat AI text embedded in images as gameplay data.
