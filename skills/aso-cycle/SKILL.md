# ASO Cycle

Use this skill when the user wants to improve public app store search discovery or listing conversion. The source workflow is Apple App Store-focused; default to Apple unless the user specifies Google Play. For Google Play, research and verify its current metadata fields and policies instead of reusing Apple's keyword-field assumptions. Treat ASO as a measurable cycle, not a promise of ranking or download growth. Work on one storefront and language at a time unless the user asks for localization.

## Workflow

1. **Define the baseline.** Identify the app, actual capabilities, platform, category, storefront and language, current listing, target users, and date current metadata/assets became effective. Clarify the primary outcome (qualified installs, search discovery, conversion, or downstream quality). Gather available analytics, ratings/reviews, and campaign/release context. If data is unavailable, say so and provide a provisional audit rather than manufacturing a baseline.
2. **Research demand and competition.** Derive seed terms from user needs, actual app functions, reviews/support language, search suggestions, and relevant competitor listings. Compare leading competitors' positioning, metadata, creative, rating/review patterns, and gaps only where verifiable. Use Google Trends for vocabulary and broad interest signals, not as store search volume. If using an ASO tool such as Astro, record source/date, storefront, Popularity, Difficulty, and Position per term; explain that tool estimates are directional. Check result-page intent and reject mismatched terms. Prioritize relevance before volume/competition; do not invent metrics or imply competitors' public metadata proves their strategy works.
3. **Turn research into a listing plan.** Map primary and secondary intents to platform-specific fields. For Apple, consider name, subtitle, keyword field, promotional text, description, category, and localized product page; distinguish fields that affect discovery from fields intended mainly to inform or convert users. For Google Play, verify its current title, short/full description, store listing experiments, and policy requirements instead of applying Apple's field model. Provide alternatives with counts and rationale when useful. Avoid keyword stuffing, unsupported claims, competitor/trademark terms, and duplicate terms where they waste constrained space. Keep feature/benefit claims faithful to the supplied product.
4. **Review the full conversion surface.** Evaluate icon, first screenshots, later screenshots, app preview/video, and description opening for a coherent promise. On Apple, make the first three screenshots explain outcome, how to start, and a differentiating capability. Use real product evidence, correct device specs, and legible concise copy. Review rating/review themes for product-page objections and unmet expectations; suggest honest issue follow-up, never incentivized or manipulative rating tactics. Consider category fit and localization where evidence supports it. Make seasonal or launch recommendations only when timing and product relevance are known.
5. **Prepare experiments or a release.** State each experiment as a hypothesis, one principal variable, audience/locale, success metric, expected evidence, and stopping/decision rule. For Apple Product Page Optimization, verify current eligibility, review requirements, available assets, and test status in App Store Connect; do not promise statistical significance or a fixed run length without traffic. For Google Play, use its current store listing experiment capability and requirements. If not experimenting, log the before state, intended change, owner/action, submission/effective date, and confounders. Verify current platform limits and policies against official documentation before submission; current requirements take precedence over remembered figures.
6. **Measure the whole funnel.** Compare equivalent storefronts, locales, date ranges, and device/platform filters where available. Track search visibility/rank (with source and observation date), impressions or product-page views, conversion/first-time installs, and activation/retention/revenue when relevant. Separate paid search/ads, featuring, seasonality, releases, price changes, and rating shifts from organic ASO interpretation. Allow at least a complete week for an initial read and longer for low volume; use platform experiment estimates and observed traffic to set expectations. A rank gain alone is not success.
7. **Diagnose and iterate.** If rank improves without exposure/install movement, check demand and actual visibility. If views rise without installs, check intent match, creative, price, ratings, and clarity. If installs rise without activation/retention, check whether onboarding and the product fulfill the listing promise. If movement is unclear, verify the change is live in the correct locale and data window. Change one major variable per cycle when practical and document other interventions.

## Deliverable

Give the user a practical ASO plan tailored to the requested scope. For a full audit, include baseline/assumptions, prioritized keyword/competitor evidence, platform-specific metadata options with character counts, listing/creative and review insights, experiment or release plan, change log, and measurement/decision rules. Do not create an arbitrary numeric “ASO health score” unless a transparent rubric and relevant inputs are available; show component evidence instead. When the user requests only one stage, do not force the rest. Browse for current platform rules, benchmarks, changing tool features, or other time-sensitive claims; prefer official store documentation for policies and capabilities. Cite browsed claims and distinguish observed facts, estimates, and recommendations.

For the detailed operating checklist and reusable report structure, read [references/aso-cycle.md](references/aso-cycle.md). For Apple product-page requirements, use the current [Apple product page guidance](https://developer.apple.com/app-store/product-page/) and [App Store Connect reference](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information); verify Google Play requirements in current official Play Console documentation when relevant.
